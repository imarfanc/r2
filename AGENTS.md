# t5

This is a Deno web repository serving a local script runbook. Use Deno tasks; do not add package-manager wrappers.

## Layout

- `src/` contains runtime code, split into `server/` (HTTP wiring and static serving), `app/` (features), and `shared/` (cross-cutting helpers). `src/config.ts` and `src/main.ts` stay at the top.
- `public/frontends/` holds one folder per frontend version plus `shared/`; each version holds one folder per script group. `tests/` contains tests.
- `data/scripts/` holds the scripts the server runs, grouped by `SCRIPT_GROUPS`, one directory per script.
- `_repo/` contains trusted local repository operations, ADRs, and skills.
- `_other/` contains everything else: notes, docs, one-off scripts, changelog, scratch work.

## Required workflow

- Run `deno task check` before handing off changes.
- Keep secrets in `.env`, never in tracked files.
- Application code must not import `_repo/` or `_other/`.
- Put new material in a subfolder of `_other/` rather than a new top-level directory, and give each folder a short `README.md`.
- Edit skills under `_repo/skills/`, never through agent-directory symlinks.
- Change the project name with `deno task rename`, never by hand.
- Every task in `deno.json` needs a matching entry in `_repo/tasks.json`, and vice versa.
- `src/shared/terminal.ts` intentionally duplicates `_repo/tools/lib/terminal.ts`; keep them in step.
- Add a frontend version by copying a folder under `public/frontends/` and listing it in `FRONTENDS`; a version must carry a page for every script group.
- `data/scripts/` is content, not repository source: it is excluded from `deno fmt`, `deno lint`, and the structural content checks, and its scripts may use any runtime. Do not reformat it.
- Shared frontend logic lives in `public/frontends/shared/`; a version folder holds only its own rendering, so a new version is a design exercise rather than a second implementation.
- `/shared/config.js` is generated by `src/app/client-config.ts`. Never add a static copy of it under `public/`.
