# Frontend design

Before implementation, state a compact visual thesis: audience, mood, typography, color logic, density, and the one interaction or composition choice that makes the interface recognizable.

- Build a clear hierarchy before adding decoration.
- Use a restrained type scale and a small semantic color system.
- Prefer layout rhythm, contrast, and whitespace over excessive cards and borders.
- Design empty, loading, error, narrow-screen, keyboard, and reduced-motion states with the primary state.
- Reuse existing project tokens and components when they express the intended direction.
- Verify the result in a real browser at narrow and wide widths.

Avoid anonymous gradients, decorative dashboards, and “AI purple” unless the product context calls for them.
